# 구조 가이드

## 코드 경계

| 위치 | 책임 |
| --- | --- |
| `src/domain/` | 이슈 타입, 필터·정렬·트리·날짜·ADF 규칙. DOM/HTTP 없이 단위 검사 |
| `src/server/connection.ts` | 인증 정보 검증·저장, 실행 중 Jira 서비스 교체 |
| `src/server/jira-client.ts` | 인증, Jira 요청, HTTP 오류 처리 |
| `src/server/jira-*.ts` | 응답 검증, 메타정보·목록·상세·본문·필드 변경 |
| `src/server/bulk-service.ts` | 공통 선택지, 부분 성공, 충돌을 보호하는 되돌리기 |
| `src/server/http.ts` | 로컬 HTTP 라우팅·입력 검증·정적 파일 제공 |
| `src/server/network-log.ts` | 모든 Jira 요청·응답 로그. 메모리에만 보관 |
| `src/server/mcp*.ts` | 동일 서비스의 읽기 전용 stdio MCP |
| `src/client/` | API 응답 경계, 계정별 저장소, 목록·편집·변경 확인 상태 |
| `src/client/app.ts` | 위 상태와 UI 연결, 화면 수명 관리 |
| `src/ui/` | 공통 카드·배지·셀렉트·팝오버·모달·알림·ADF 편집 및 기능별 화면 |
| `tests/` | 가짜 HTTP를 사용하는 Node 자동 검사와 브라우저 검사 페이지 |

UI는 공유 `issueCard`·`meta`·`select-menu`·`modal`·`document-form` 등을 사용합니다. 상대 시각은 `domain/dates.ts`, 상태 색상은 `ui/meta.ts`, 복사는 `ui/clipboard.ts`가 담당합니다. 변경 시 해당 경계에서 수정하고 다른 화면에 동일 로직을 복제하지 않습니다.

## 조회와 변경

- 서버는 인증 정보가 없어도 로컬 화면을 제공합니다. 브라우저 연결 시 `/myself`로 현재 계정을 매번 확인하고 프로젝트·상태·유형·우선순위 정보를 준비합니다. 상태는 보드 순서를 우선 사용하고 조회 권한이 없으면 Jira 상태 범주 순서를 사용합니다.
- 목록 검색·필터·정렬은 서버 JQL 기반입니다. 페이지는 Jira `nextPageToken`을 보존하는 커서이며, 아래로 스크롤하면 다음 페이지를 읽습니다.
- 목록의 조상은 키를 모아 묶음 조회합니다. 접힌 분기의 하위는 읽지 않습니다. 펼친 분기는 부모별 커서 조회를 중복 방지하고 최대 3개씩 실행합니다. 트리·상세 중 한 곳이라도 열려 있으면 조회를 유지하고 모두 닫히면 대기 요청과 후속 페이지 조회를 멈춥니다. 앱 종료 후 늦은 응답은 반영하지 않습니다. 부모별 뷰를 지원하므로 모든 하위를 한 번에 읽지 않습니다. 목록과 상세는 같은 조건 해석과 하위 캐시를 공유합니다.
- 프로젝트 목록은 동시 요청을 합쳐 5분간 재사용합니다. 인증은 진행 중 요청만 합치고 다음 연결에서 재검증합니다. 뷰 선택만으로는 편집 선택지를 읽지 않습니다. 조건 편집을 펼칠 때 조회하고 같은 프로젝트의 요청을 합쳐 5분간 재사용합니다. 멤버 목록은 직접 선택할 때만 조회하고 같은 사이트의 후보를 5분간 재사용합니다. 프로젝트는 별도 선택 팝오버에서 초안을 고른 뒤 적용하며 저장된 뷰를 변경하지 않습니다. 초안은 적용할 때 반영합니다. 캐시 키는 뷰 이름/ID가 아닌 실제 조건이므로 등록·이름 변경은 재조회하지 않습니다. 전체 조건을 바꿔도 조건이 같은 완료된 하위 캐시는 유지합니다. 담당자·상태·유형·우선순위·기본 우선순위는 5분 메모리 캐시로 중복 요청을 합칩니다.
- 목록과 읽은 하위는 IndexedDB에 사이트·계정·조회 조건별로 저장합니다. 새로고침은 `/myself` 인증 뒤 캐시를 먼저 표시하고 `/api/sync`로 프로젝트 변경분과 기존 고정 ID의 존재·수정 시각·부모·프로젝트를 확인합니다. 가벼운 대조는 1,000개, 변경 상세는 100개씩 묶습니다. `issueErrors`·부분 실패를 삭제로 해석하지 않으며, 조회 시작 시각을 성공 시에만 저장하고 검색 구간을 2분 겹칩니다. 닫힌 분기도 이미 캐시된 ID의 존재 대조에는 포함하지만 하위 목록 검색은 하지 않습니다.
- ID 없는 기존 캐시, 6시간 이상 정합성 미확인, 변경 1,000개 초과는 이전 범위를 다시 검증합니다. 부분 목록의 추가 읽기는 옛 커서를 쓰지 않고 새 커서로 이전 범위와 다음 페이지를 잇습니다. 변경 없는 목록·상세 하위·최근 카드 DOM과 포커스는 유지하며, 읽던 카드 위치는 `ui/viewport-anchor.ts`로 복원합니다. 계정별 최근 10개 쿼리, 쿼리당 하위 페이지 100개·5MiB, 7일 보관입니다. 커서·토큰·본문·댓글은 저장하지 않으며 저장소 실패는 일반 조회로 복구합니다. 상세 본문 캐싱은 후속 검토입니다.
- 상세 본문·댓글·첨부 정보는 선택 시 읽습니다. 하위·변경 기록·편집 선택지는 필요할 때 읽습니다. 이미지 프록시는 상세에서 받은 첨부 메타정보를 재사용합니다.
- 필드 변경은 변경된 이슈와 필터 일치 여부를 조회해 목록·상세·최근 카드에 반영합니다. 일괄 변경도 전체 목록을 다시 불러오지 않습니다. 권한·상태 전환이 이슈마다 다르므로 공통 선택지 확인은 이슈별로 필요합니다.
- 최근 변경 확인은 선택한 프로젝트의 `updated` 변경분을 묶음 조회합니다. 화면을 보고 있을 때 주기 확인하며 수정 중인 초안은 보존합니다. 웹훅·웹소켓을 사용하지 않습니다.
- 되돌리기는 서버 메모리에 보관하므로 재시작 후에는 사용할 수 없습니다. 이후 외부 수정과 충돌하면 덮어쓰지 않습니다.

## 뷰 모델과 책임

- `domain/views.ts`: 조건 정규화·동일 조건 비교·참조 해석·등록·삭제·이전의 순수 함수입니다. `ViewDefinition`은 담당자 범위·선택 단계·담당자·완료 제외·다중 정렬만 담으며 프로젝트/검색은 전체 탐색 범위로 분리합니다.
- `ViewBinding`은 `default`, `inline(definition)`, `saved(viewId)` 중 하나입니다. 부모의 기본 뷰는 전체 뷰를 따릅니다. 부모에서 공용 조건을 편집하면 전용 뷰로 분리되고, 관리 화면에서만 공용 정의를 수정합니다. 삭제 시 마지막 조건은 전용 뷰로 남깁니다.
- `client/view-controller.ts`: 적용·저장·일시적 넓혀 보기를 조정합니다. `view-editor-controller.ts`는 독립 초안, `view-options.ts`는 메타정보 조회를 담당합니다. 저장 성공 후에만 상태를 바꾸며 실제 조건 변화는 일괄 선택을 해제합니다.
- `ui/view-editor.ts`·`filter-checklist.ts`·`sort-editor.ts`: 팝오버와 관리 화면이 재사용하는 조건 편집기입니다. `view-picker.ts`는 참조 선택, `view-manager.ts`는 등록·복제·공용 편집·삭제를 담당합니다.
- `ViewState(version=1)` 하나에 공용 정의와 전체/부모 참조를 함께 저장합니다. 저장소 키는 사이트·계정별로 구분합니다. 이전 필드별 상속은 당시의 유효 조건으로 이전합니다. 단계·담당자는 순서/중복을 무시하되 전체(null), 없음([]), 정렬 우선순위는 구분합니다.
- 사람 조건은 담당자/작업 관계자 기준과 내 작업/전체/직접 선택으로 해석합니다. `domain/people.ts`는 조건 전이, `ui/people-filter.ts`는 공통 표시를 담당합니다. 작업 관계자는 담당자와 Jira에서 조회한 검색 가능한 사용자 타입 custom field를 포함하며 단일·복수 사용자 필드를 지원합니다. 직접 선택한 계정은 해당 필드들에 OR로 적용합니다.
- 목록·하위·최근 변경·상세는 관련 계정 ID를 함께 전달해 같은 판정 규칙을 사용합니다. 내 담당만은 미지정을 제외하며 필요하면 직접 선택의 ‘나 또는 미지정’ 액션을 사용합니다. 일시적 완료/다른 사람 포함은 저장 조건을 바꾸지 않습니다.
- 필터 후보는 담당 가능 사용자로 제한하지 않고 사용자 디렉터리의 활성 멤버를 페이지로 조회·캐시하며 앱 계정은 제외합니다. Jira의 사용자 조회 권한을 따르며 해당 권한이 없어도 내 작업·단계·정렬 편집은 사용자 목록 조회 없이 동작합니다. 전체 선택은 전체 조건(null), 직접 선택은 최대 200명으로 저장·복원·조회 상한을 공유합니다.

## 인증과 제약

`.env`의 사이트·이메일·토큰으로 REST Basic 인증을 합니다. 최초 연결·토큰 만료 시 설정 화면에서 발급 안내를 따라 새 토큰을 입력합니다. `/api/connection`은 사이트·이메일만 반환하고, 로컬 화면의 저장 요청은 인증에 성공한 값만 권한 `0600`으로 저장한 뒤 서비스를 교체합니다. 재시작은 필요하지 않으며 실패한 토큰은 기존 설정을 덮어쓰지 않습니다. ACLI는 사용하지 않습니다. 로컬 HTTP는 Origin 검증과 입력 검증을 유지하며 외부 공개 서버 용도로 설계되지 않았습니다. 개발자 로그에는 인증 헤더를 담지 않지만 이슈 본문 등 업무 데이터가 포함될 수 있습니다.

답글은 공개 REST에 문서화된 부모 댓글 필드가 없어 Jira 내부 동작에 의존합니다. 댓글 좋아요·이모지 반응은 지원하지 않습니다. 첨부·보드·생성 메타 권한에 따라 일부 보조 정보는 표시되지 않을 수 있습니다.
